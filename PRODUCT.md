# IMPOSTER

The discussion roster includes an optional public clue history, with one short clue per player per clue turn. The host can start further clue turns or open voting without requiring submissions. Roles, word, scoring, and imposter-selection history stay unchanged across clue turns. Players may edit/remove their own recorded clues until voting; voting and runoff show the full read-only history. Host memory preserves it across reconnects and clears it for the next game round. See design/clue-board-v2/README.md.

Android-first local social deduction game, built with Tauri 2, Rust and React. iOS is a later target. Product rules and authority boundaries live in PLAN.md; word catalog lives in TOPICS.md. No accounts, cloud party service, discussion timers, AI dares, or role rotation. One imposter selected with private fairness weights each round always gets an indirect starting hint. Everyone votes privately; correct civilians earn +1, optional confidence bets settle from the original ballot, every third correct civilian read earns +1, and escaping imposters earn +2 plus +1 for a perfect bluff. One runoff, then imposter escape on a repeated tie. Human-given dares, sequential punishment turns, and session rankings race to a host-selected target of 10, 15, 20, 25, or 30 points. See PLAN.md for complete mechanics.

The user approved design/proposal-v1/*.png and requested faithful implementation with animations. This is implementation authorization, not an open visual exploration. Do not replace the approved design with generated alternatives.

After results, each player can privately report several other players or skip on a dedicated screen. Missing submissions and skips count as no reports. A strict majority of the full round roster schedules −1 point after the following completed round's normal scoring; all deductions stop at zero. Reports reset each round, and the host can continue without waiting. Reporting never changes Drink/Dare eligibility. See PLAN.md for timing, privacy, and reconnection rules.

Before every round, all participating players approve one or more available topics. Tallies stay hidden until all ballots lock; the top total wins and tied leaders have equal random chances. The host reveals a tie draw once, then continues to private roles. See design/topic-voting-v1/README.md.

Session scoring follows the approved design/session-scoring-v1 mockups. The target locks at the first round and final totals remain visible after the target is reached. Highest final score wins, with shared wins for tied leaders. The host starts the next score session explicitly: scores, reading streaks, bets, and pending report deductions reset; connected players, join credentials, topic settings, used-word history, and imposter fairness history stay with the party. See design/session-scoring-v1/IMPLEMENTATION.md for the settled rules and verification.
